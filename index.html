Replace the unreliable sleep

driver.findElement(By.id("submit")).click();
Thread.sleep(3000);

String status = driver
    .findElement(By.id("status"))
    .getText();

assertEquals("Completed", status);

Task

  • Rewrite this using an explicit wait.

  • Make timeout failures explain the last status that was observed.
5–8 minutesSelenium

Fix the stale-element bug

List<WebElement> cards =
    driver.findElements(By.cssSelector(".flight-card"));

for (WebElement card : cards) {
    if (card.getText().contains("FRA–JFK")) {
        card.findElement(By.cssSelector(".select")).click();
    }
}

Clicking a card causes the full card list to re-render. The test intermittently throws StaleElementReferenceException.

Questions

  • Refactor the code so it does not retain stale element references.
  • How would you verify that the correct flight became selected?
  • Would retrying every stale-element exception be a good framework-level policy?

5 minutesParallel execution

Explain why this fails only in CI

public class BaseTest {
    protected static WebDriver driver;
    protected static String bookingId;

    @BeforeEach
    void setup() {
        driver = DriverFactory.create();
        bookingId = TestData.createBooking();
    }

    @AfterEach
    void cleanup() {
        TestData.deleteBooking(bookingId);
        driver.quit();
    }
}

Questions

  • Why can this pass sequentially but fail when tests run in parallel?
  • Show the smallest safe refactoring.
  • When would ThreadLocal<WebDriver> be justified, and what cleanup is mandatory?
