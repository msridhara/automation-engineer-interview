Live coding20 minutesCore Java

Build a reusable polling utility

Implement the method below. It should repeatedly evaluate a condition until it returns a value accepted by the caller or the timeout expires. 

public final class PollingWait {

    public static <T> T until(
            Supplier<T> action,
            Predicate<T> success,
            Duration timeout,
            Duration interval) {
        // Implement
    }
}

Requirements

  • Execute the action immediately, then poll at the requested interval.
  • Return the successful value without an unnecessary additional wait.
  • Reject invalid timeout or interval values.
  • Preserve thread interruption correctly.
  • On timeout, provide useful diagnostic information without hiding the last failure.
  • Make the code testable without forcing unit tests to wait in real time.
Discuss: How would you unit-test timeout, success, exceptions, and interruption deterministically?
Refactoring20 minutesSelenium

Make this UI test reliable and maintainable

Review the test, identify its risks, and refactor enough code to demonstrate your preferred design.

@Test
void customerCanBuyExtraBag() throws Exception {
    WebDriver driver = new ChromeDriver();
    driver.get(BASE_URL + "/booking");
    driver.findElement(By.id("booking-code")).sendKeys("ABC123");
    driver.findElement(By.xpath("//button[text()='Continue']")).click();
    Thread.sleep(5000);
    driver.findElements(By.cssSelector(".passenger-card")).get(0).click();
    driver.findElement(By.xpath("//div[contains(text(),'Add baggage')]")).click();
    Thread.sleep(3000);
    driver.findElement(By.cssSelector("input[value='23kg']")).click();
    driver.findElement(By.id("confirm")).click();
    assertTrue(driver.getPageSource().contains("Baggage added"));
    driver.quit();
}

Your task

  • Explain the reliability, readability, lifecycle, and diagnostic problems.
  • Refactor selectors, synchronization, browser cleanup, and assertions.
  • Show how page/component objects should expose business behavior without becoming wrappers for every element.
  • Explain how you would handle asynchronous updates, localization, multiple passengers, and test data.
Discuss: When would you avoid a Page Object, and what evidence would you capture on failure?
Live coding20 minutesREST Assured

Test an idempotent ancillary-order API

Design and code tests for the following endpoint:

POST /v1/bookings/{bookingId}/ancillaries
Headers:
  Idempotency-Key: <unique-key>
  Authorization: Bearer <token>

Request:
{
  "passengerId": "P1",
  "type": "BAGGAGE",
  "option": "23KG"
}

Success: 201 Created
Duplicate key + identical body: 200 OK, same orderId
Duplicate key + different body: 409 Conflict

Your task

  • Implement the three core scenarios using REST Assured and clear domain assertions.
  • Keep request construction, authentication, and response models maintainable.
  • Validate meaningful headers, schema/domain fields, and side effects—not only status codes.
  • Explain isolation, cleanup, parallel execution, observability, and eventual consistency.
Discuss: Where should contract tests end and end-to-end tests begin?
Diagnosis15 minutesCI reliability

Investigate a flaky parallel test

The test passes locally but fails about 8% of the time when the CI suite runs eight tests in parallel.

public class SearchTests {
    private static WebDriver driver;
    private static String bookingId;

    @BeforeAll
    static void setup() {
        driver = DriverFactory.create();
        bookingId = TestData.createBooking();
    }

    @Test
    void searchShowsPassenger() {
        driver.get(url("/search"));
        searchFor(bookingId);
        wait.until(visibilityOfElementLocated(By.cssSelector(".result")));
        assertEquals("MURALI", driver.findElement(By.cssSelector(".name")).getText());
    }

    @AfterAll
    static void cleanup() {
        TestData.deleteBooking(bookingId);
        driver.quit();
    }
}

Explain your investigation

  • Rank likely causes rather than changing several things at once.
  • Describe the evidence and telemetry you need to prove each hypothesis.
  • Propose the smallest safe fix and a longer-term prevention strategy.
  • Explain retry policy, quarantine criteria, and how flakiness should be measured.
Constraint: “Add a retry” is not an acceptable root-cause fix.
System design15 minutesWhiteboard

Design automation for a multi-airline ancillary platform

A platform serves four airlines, web and mobile channels, 12 markets, multiple payment methods, and three environments. Teams release independently several times per week.

Design a strategy that covers

  • Test layers and ownership across developers, QA, and platform teams.
  • Repository/framework boundaries and reusable domain abstractions.
  • Data creation, environment configuration, secrets, and parallel execution.
  • PR, deployment, scheduled, and release-gate pipelines.
  • Selection by risk, changed component, airline, market, and channel.
  • Reporting, traceability, observability, flaky-test control, and maintenance.
Trade-off: You may run only 10 minutes of automation on each pull request. Explain what runs and why.
